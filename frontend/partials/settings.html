Heavy pass
Run at
Every

Indexing, snapshot analysis, reclaimable, the dashboard rebuild, folder pre-compute and the Backblaze rescan all run together in a separate process that exits afterwards, so this app never holds on to the memory. One repo at a time. If the PC was off at the scheduled time it catches up at the next opportunity. The app stays usable while a repo indexes; a heavy pass just isn't included in that repo's numbers until it finishes.

Dashboard numbers

The physical / freeable / dedup columns take about 80 seconds to recompute. Nightly keeps that out of your day; the ↻ Refresh button rebuilds them on demand either way.

Full rebuild

Re-walks every snapshot in this repo from scratch instead of only what changed. Rarely needed; takes far longer than a normal pass.

Background warm pass

The cheap in-process pass: next-snapshot times, repository stats and the search landing page. Everything expensive now rides with the heavy pass instead.

Dashboard auto-refresh

How often an open Dashboard re-fetches the cached numbers. Cheap: just a re-render when something changed.

Dashboard rebuild interval

Only used when Dashboard numbers is set to "Also rebuild during the day". Ignored otherwise.

When quitting KopiaLens

Restart always lets indexing finish. A stopped run is retried later.

Folder pre-compute budget
seconds

Wall-clock cap on the nightly stage that pre-computes folder reclaim, biggest folders first. Anything it does not reach is computed when you open it. 0 disables the stage (it never means "no limit"). The depths it works at follow the Churn tab and bloat-finder depths automatically.

Quiet period after startup restart
seconds

How long after launch before any background work starts, so booting the PC is not immediately followed by a burst of disk and CPU.

Background cycle gap
seconds

Sizes the quiet period after a restart, so restarting just after a cycle does not start another one. Only used when the heavy pass runs on an interval.

Debug log

Writes detailed diagnostics to data/logs/kopialens-debug.log, alongside the normal app log. Useful when troubleshooting; leave it off otherwise. Applies immediately.

Log cleanup

Removes old job, dry-run and mount logs from data/logs/jobs. The newest 100 are always kept.

Ranked files

How many files the nightly ranks exactly so Search can sort by Stored and Frees. Higher counts cost a few extra seconds per run.

Backblaze data folder restart

Where the Backblaze client keeps its file lists. Read-only - KopiaLens never writes here.

File index format

Where the scanned file list is stored. Parquet is about 20x smaller and faster to query. SQLite is the legacy format, kept for rollback. Switching rebuilds the new store on the next Backblaze rescan; once the Parquet build succeeds, the space the old copy occupied is reclaimed automatically.

Reindex minimum gap

Changes in Backblaze's own scans are detected within half an hour; this gap sets how long the reindex then waits. Smaller means fresher numbers and more reindexing.

History retention
days

How many days of per-folder rollups to keep for the growth and churn trend.

Collapse prefixes

Comma-separated paths that show as one row in the Queue, Churn and by-folder views instead of splitting into their chunk-named subfolders.

Session history folder

Readable copy of the rotated Backblaze event logs, used by "Import archived history" on the Sessions tab. Leave empty to skip.

Changes save as you make them. Scheduling and interval changes apply within a minute; items marked restart need one.
